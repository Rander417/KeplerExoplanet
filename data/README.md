# Data

Every dataset in this project traces back to the [NASA Exoplanet Archive](https://exoplanetarchive.ipac.caltech.edu/) **Kepler Objects of Interest (KOI) cumulative table**. This file records where each copy came from, so results can always be tied to a specific snapshot.

## Folders

| Folder | Tracked in git? | Contents |
|---|---|---|
| `raw/` | yes | Source files exactly as downloaded. Never edited by hand. |
| `processed/` | no (regenerated by the notebooks) | Cleaned / feature-engineered tables written as parquet. `koi_clean.parquet` (notebook 01): every KOI, uncertainty columns dropped, `koi_score_missing` / `has_kepler_name` / delivery dummies added, nothing dropped. |
| `legacy/` | yes | The pickles produced by the 2020 notebooks. Kept so the refreshed pipeline can be checked against the original outputs. |

## `raw/cumulative_kaggle_snapshot.csv`

* **What:** the KOI cumulative table, 9,564 rows x 50 columns.
* **Origin:** downloaded in 2020 from Kaggle, [NASA "Kepler Exoplanet Search Results"](https://www.kaggle.com/nasa/kepler-exoplanet-search-results), which is itself an export of the archive's cumulative table. The exact archive snapshot date behind the Kaggle export has **not been verified**; the delivery names in the file include `q1_q17_dr25_tce`, so it post-dates the DR25 release.
* **Disposition counts in this file:** CONFIRMED 2,293 / CANDIDATE 2,248 / FALSE POSITIVE 5,023.
* **Formerly:** `Resources/cumulative.csv` (renamed in the 2026 refresh; git history follows the file).

## `raw/stellar_info_final.csv`

* **What:** 7,810 rows x 7 columns: `kepid`, `koi_smet` (+ err1/err2), `koi_smass` (+ err1/err2).
* **Origin:** a second pull of stellar metallicity and mass from the same archive table, joined on `kepid` for the habitable-zone analysis. These columns are part of the cumulative table itself, so a fresh TAP pull (below) makes this file unnecessary.
* **Formerly:** `Resources/stellar_info_final.csv`.

## Live pulls (Phase 3)

The archive's Table Access Protocol service returns the current cumulative table directly. Documentation: [Retrieving Exoplanet Archive Data With Table Access Protocol](https://exoplanetarchive.ipac.caltech.edu/docs/TAP/usingTAP.html). Example (CSV, all columns):

```
https://exoplanetarchive.ipac.caltech.edu/TAP/sync?query=select+*+from+cumulative&format=csv
```

Live pulls will be saved as `raw/cumulative_tap_YYYY-MM-DD.csv` so the pull date is never ambiguous. For reference, on 2026-08-24 the live table reported CONFIRMED 2,747 / CANDIDATE 1,978 / FALSE POSITIVE 4,839 (same 9,564 KOIs).

## A note on the two disposition columns ("the tale of two Ys")

`koi_pdisposition` is what the Kepler pipeline's automated vetting concluded from Kepler data alone (CANDIDATE or FALSE POSITIVE). `koi_disposition` is the archive's current verdict, which adds follow-up work and confirmations (CANDIDATE, FALSE POSITIVE, or CONFIRMED). The four `koi_fpflag_*` columns are the reasons the vetting gave for a FALSE POSITIVE, which is why they nearly determine `koi_pdisposition`. See `notes/Decisions/` for how the refreshed models treat this.
